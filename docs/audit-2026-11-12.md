# Audit Qwebbo, 12 novembre 2026

Classement par effet sur la vente à ESADE. Taille du correctif : S (moins d'une heure), M (une demi-journée), L (plusieurs jours).
Vérifié le 12/11/2026 : `npm test` (157 tests verts), lecture du code, chargement de pages de production en lecture seule, requêtes SQL en lecture seule (totaux uniquement, aucune donnée personnelle lue).

## 1. Le contenu ESADE est public aujourd'hui (S pour toi, bloquant)
- **Le dépôt GitHub est public.** `https://raw.githubusercontent.com/aloysdeboissezon/tipoki/main/api/_esade/banks/compta2.js` répond 200 : n'importe qui lit les questions ESADE sans compte.
- **La barrière ESADE est ouverte en production.** `api/esade.js:14` et `js/app/03-quiz-data.js:267` ont `ESADE_OPEN = true` (« mode ouvert temporaire »). `https://qwebbo.com/api/esade?k=bank&id=socio` répond 200 sans connexion (241 Ko).
- **L'historique git garde les anciennes versions** de `js/banks/socio.js` et `js/banks/compta2.js`, publiques jusqu'à la PR #137 (commit `a0f28dd`).
- Correctif : (a) rendre le dépôt privé (GitHub → Settings → Danger Zone → Change visibility) ; (b) repasser `ESADE_OPEN` à `false` dès que l'envoi des codes par e-mail est vérifié sur un téléphone.
- Ce que « privé » règle : plus personne ne peut lire le dépôt ni son historique à partir de ce moment. Ce que ça ne règle pas : les copies déjà faites (clones, forks, caches) ; le contenu déjà servi par le site pendant le mode ouvert.

## 2. Les chiffres d'usage du deck ne correspondent pas à la base (S, décision d'Aloys)
Ce que la base mesure (projet Supabase créé le 21/10/2026) :

| Mesure | Valeur | Définition exacte |
|---|---|---|
| Parties multijoueur créées | 92 | lignes de `games`, depuis le 21/10 |
| Participations en multijoueur | 175 | lignes de `players` (une par joueur et par partie) |
| Appareils distincts en multijoueur | 32 | `pid` distincts dans `players` |
| Réponses données en multijoueur | 2 880 | réponses enregistrées dans `players.ans` |
| Parties terminées (solo + multi), depuis le 30/10 | 65 lignes, 47 parties | `play_stats` (ajoutée le 30/10) |
| « Joueurs » depuis le 30/10 | 50 | couples (quiz, appareil) : un même appareil compte une fois par quiz |
| Réponses depuis le 30/10 | 1 185, dont 819 justes (69,1 %) | `play_stats` ; multi seul : 830 réponses, 66,9 % justes |
| Comptes créés | 7, dont 1 avec e-mail ESADE vérifié | `tpk_accounts` |

- **« 4 000 joueurs uniques » n'est pas confirmé** : la base compte quelques dizaines d'appareils. Si ce chiffre vient de Vercel Analytics, ce sont des visiteurs ou des pages vues, pas des joueurs : il faut le nommer ainsi et garder la capture comme source.
- « 1 700 réponses en live » : la base en compte 2 880 (mieux). « 65 % de bonnes réponses » : 66,9 % en multi et 69,1 % au total depuis le 30/10. Le « 70 % » du deck v7 ne vient d'aucune mesure.
- `site_stats` (`supabase/migrations/add_analytics.sql:70`) compte les « players » par quiz : la page `/?stats=all` gonfle donc le nombre de personnes.
- Correctif : le deck v8 n'affichera que ces chiffres, avec leur définition. Une école de commerce vérifiera.

## 3. Le différenciateur n'existe pas encore dans le produit (L, en cours)
« Les professeurs envoient leur cours, Qwebbo crée le reste, ils relisent et approuvent » : aujourd'hui c'est fait à la main, hors du site. Aucun écran professeur, aucune relecture, aucune trace d'approbation. `supabase/functions/generate-quiz/index.ts:42` est écrit pour des étudiants et ne cite aucune source. C'est le chantier principal (voir `docs/professor-workflow.md`).

## 4. Aucune question ne cite sa source (M)
Les 4 banques ESADE (1 820 questions) n'ont ni page ni citation du cours. Le deck promet un contenu vérifiable. Le nouveau format de kit (`docs/kit-format.md`) rend la source obligatoire pour tout nouvel item ; les banques existantes restent sans source tant qu'un professeur ne les a pas relues.

## 5. Qualité des banques : 0 erreur bloquante côté ESADE, 7 doublons dans les traductions publiques (S)
`node tools/check-kit.js` (nouveau, 25 414 items dans toutes les langues) : 0 erreur dans socio, compta2, populism, regression. 7 doublons exacts dans les traductions de foodtravel (es, fr, ko), energie (ko), kids (ko, 2), myths (ko), parce que deux questions presque identiques en version originale deviennent identiques une fois traduites. 2 154 avertissements, surtout « la bonne réponse est nettement plus longue que les autres » (116 dans socio, 77 dans regression, 64 dans compta2) : un étudiant malin peut deviner. À corriger banque par banque avec le professeur.

## 6. Le tableau de bord enseignant du deck est illustratif (M, en cours)
`/?stats=<quiz>` (`js/stats.js`) existe mais il faut un code donné à la main, il n'y a ni seuil d'anonymat ni indicateurs du pilote. La diapositive 12 du deck montre une maquette. Le nouveau tableau calcule activation, retour hebdomadaire, progression, questions les plus ratées, et n'affiche rien sous 5 étudiants.

## 7. Pas d'export vers Moodle, pas de téléchargement du contenu (M, en cours)
ESADE utilise Moodle d'après ses pages publiques. Rien ne sort de Qwebbo aujourd'hui. Exports ajoutés : GIFT, Moodle XML, CSV, pages imprimables (PDF), avec la mention de licence.

## 8. Sécurité : base correcte, trois points à fermer (S à M)
- Vérifié en base : RLS activé sur les 18 tables ; les migrations `harden_security`, `add_analytics`, `add_esade_access` sont bien appliquées (déclencheurs et fonctions présents) ; aucun bucket de stockage.
- Pas d'en-tête `Content-Security-Policy` (`vercel.json:33`). 46 usages de `innerHTML` dans le moteur : un contenu importé mal échappé pourrait injecter du script. L'espace professeur est écrit sans `innerHTML` pour le contenu saisi et sa page reçoit une CSP stricte.
- `generate-quiz` accepte `ALLOWED_ORIGIN` absent = `*` (`index.ts:16`) : à fixer à `https://qwebbo.com` avant d'activer l'IA.
- La clé de `stats_keys` circule dans l'URL (`/?stats=…`) : remplacée par le compte professeur.

## 9. Le prix du deck se contredit (S)
v7 affiche « 0,1 % des frais de scolarité ≈ 21 € par étudiant », soit environ 160 000 € par an pour 7 700 étudiants, et nulle part 80 000 €. v8 : une seule histoire de prix, 80 000 € par an (environ 10,40 € par étudiant) après un pilote de 10 000 € déduit de la première année.

## 10. La démo en direct n'a pas de filet (S)
Elle dépend du Wi-Fi, de l'arrivée de l'e-mail de code et du QR code. Un mode démo isolé de la production (données fictives étiquetées, remise à zéro en un clic) et un script de 10 minutes avec une solution de repli par étape sont prévus.

## Autres constats
- 1 seul compte ESADE vérifié en base : le parcours « e-mail ESADE → code → quiz » n'a presque jamais été joué en vrai. À tester sur téléphone avant de refermer la barrière.
- Les banques ESADE n'existent qu'en anglais (pas de version ES).
- `README.md` et `docs/esade-acces.md` décrivent la barrière comme fermée : à mettre à jour quand elle le sera.
- Répétition espacée : **corrigé après relecture du code**. Elle existe déjà : boîtes de Leitner sur les cartes (retour à 10 min si ratée, puis 1, 3, 7, 16, 35 jours), synchronisées avec le compte (`js/app/07-end-flashcards.js`, `js/sync.js`), plus les « points faibles » (une question sort de la liste après 3 bonnes réponses de suite, `js/weak.js`) et le panneau « Aujourd'hui ». Il manquait seulement un test : `tests/leitner.spec.js` le vérifie maintenant sur un cours publié par un professeur.
